ProfitPilot Barber · App Map

A short guide to where things live, so the next change starts in the right file.

What it is

A dashboard for a small barber shop owner. It shows money kept, earnings per chair-minute, busy hours, where the money went and plain-language tips, all from a month of sales imported as a CSV. Everything runs in the browser and is saved on the device; nothing is uploaded.

  • The core: src/core/. Pure functions for money, CSV reading, the month maths, tips, the planner, reports and reminders. No screen, no storage. Every function is covered by test/.
  • The app: src/app/. The screens (views/), the shared UI pieces (ui/), routing, and the single update cycle in main.js.
  • Saving: src/app/store.js. One JSON document in localStorage under profitpilot-barber.v1.

One action, end to end: importing a CSV

Sample months and example sheets come from src/core/sample.js and follow the same route.

The route, three stops

A reference route through the current code, so you can follow one import by searching for these names.

  1. 1. The screen starts the import: src/app/views/import.js → begin() Reads the file's text, runs the importer, and decides which step comes next: "Replace them with this file?" for a month that's already stored, then "New in this file" for new names and prices over R5 000.
  2. 2. The file becomes sales: src/core/importer.js → importSales() Uses parseCsv() (src/core/csv.js: separator detection, quoted fields, real line numbers) and parsePrice() (src/core/money.js: "R 1 200,00", "(120.00)", the decimal rule). Only the six known columns are ever read. Then checkStepAnswers() and applyImport() turn the owner's answers into the saved document.
    The price rule in one comment
    // The last "," or "." followed by exactly 1–2 digits is the decimal mark;
// every other "," or "." is a thousands separator.
// "1,200" → 1200, "120,5" → 120.50, "1.200,00" → 1200
  3. 3. Save, recalculate, redraw: src/app/main.js → update() Every change in the app goes through here: store.save(), then summarise() (src/core/month.js) for each month, then the current page redraws. Money is in cents throughout, which is why a R760 edit moves Money Kept by exactly R760.

A practice to reuse

Try a deliberately messy real-shaped file, then lock what it finds into a test. The parser's unit tests passed, but importing a hand-made messy CSV during the slice 3 check found a gap. A new service whose only sale was a free cut was pre-filled with a R0 list price, which blocked the import. The fix came with a test that keeps it fixed: test/importer.test.js → "a new service whose only sales were free cuts can still be imported".

On another project with outside data (bank statements, booking exports, spreadsheets from a client), keep one ugly sample file next to the code. Run it before calling the import done, and turn each surprise into a named test.
